### What was incorporated

1. **Methodology playbooks → `skills/*/SKILL.md`**

   The vulnerability-testing methodology in the following skills is derived from
   CyberStrikeAI's agent-skill set, **substantially rewritten** for ARTEX's own tool
   vocabulary (`record_fact` / `report_finding` / `insert_assets` / `node_detail` /
   `traffic_*` / `Bash` / `WebFetch`), its graph model, and its coverage ledger:

   - `pentest-verification`, `pentest-blackboard`, `component-vuln-intel`,
     `attack-surface-recon`, `web-attack-methods`, `capability-primitive-search`,
     `zero-day-discovery`, `source-code-hunting`, `specialized-attack-playbooks`,
     `active-directory-attack`, `cloud-attack-methods`, `ai-llm-app-attack`,
     `blockchain-contract-attack`, `binary-mobile-reversing`,
     `wireless-hardware-attack`, `initial-access-phishing`, `post-exploitation`,
     `redteam-opsec`, `pentest-output-standards`, `pentest-agent-os`

   Deliberately **not** ported: `unlimited-attack-scope` and `proxy-tool-bootstrap`.
   Both conflict with ARTEX's model — operation constraints (`set_constraints`) are
   the platform's top-priority red line, and egress/proxy handling is owned by the
   recording proxy + `global_proxy` setting.

2. **Scanner tool recipes → `db/toolrecipes.json`**

   Generated by `scripts/yaml2artex` from CyberStrikeAI's `tools/*.yaml` command
   definitions (name, description, parameter list, CLI flags). The YAML files are
   **not** vendored; only the derived, regenerated JSON is checked in.

   Transformations applied during conversion: parameter lists become JSON Schema;
   flags become shell templates; `additional_args` / `scan_type` free-text escape
   hatches are dropped (ARTEX shell-quotes every placeholder, so a multi-token
   free-text slot would collapse into one argument); inline-interpreter recipes
   (`python3 -c <script>`) and non-shell `internal:` handlers are excluded.

   To regenerate after updating the upstream recipe set:

   ```sh
   go run ./scripts/yaml2artex -src <path-to>/CyberStrikeAI/tools -dst db/toolrecipes.json
   ```

### What was NOT incorporated

CyberStrikeAI's orchestration layer (Eino ADK deep / plan-execute / supervisor
modes), its SQLite project-fact store, its knowledge-base RAG implementation, and
its web UI. ARTEX keeps its own planner → exploration graph → claim-based intents →
N-worker design.
