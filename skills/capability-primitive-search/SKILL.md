# 能力原语搜索（没有单个高危洞时，怎么拼出高危）

大多数真实入侵不是"一个 RCE 洞"，而是**一串低危**：信息泄露拿到内部路径 → 路径穿越拿到配置
→ 配置里有凭据 → 凭据进后台 → 后台上传 getshell。规划者看不到这条链，因为每一步单独看都"没价值"。

本 skill 的唯一职责：**把散落的低危结论翻译成"原语"，再找拼法。**

## 一、六个原语

| 原语 | 含义 | 典型来源 |
|---|---|---|
| **READ** | 能读到本不该读的内容 | 任意文件读取、IDOR 读他人数据、备份文件、日志泄露、S3 列目录 |
| **WRITE** | 能写到本不该写的位置 | 上传、日志注入、配置导入、模板编辑、任意文件写 |
| **EXEC** | 能让目标执行代码/命令 | 反序列化、SSTI、命令注入、表达式注入、依赖劫持 |
| **AUTH** | 能变成另一个身份 | 凭据泄露、JWT 伪造、默认口令、会话固定、OAuth 绕过 |
| **NET** | 能触达内网/元数据 | SSRF、DNS 外带、代理穿透、内网端口转发 |
| **SIGNAL** | 能确认"对方处理了我的输入" | 时间差、报错差异、DNS 回连、状态码差异 |

（SIGNAL 本身不是漏洞，但它是把"猜"变成"证"的唯一手段。）

## 二、正向搜索：从原语找落点

拿到一个原语后，问四个问题：

1. **READ + 什么 = 高危？**
   读配置（凭据）→ AUTH；读源码（找下一个洞）→ 更多原语；读密钥（签名/加密）→ AUTH 或 EXEC。
2. **WRITE + 什么 = 高危？**
   写 web 目录 + EXEC；写 cron/启动脚本 + EXEC；写 `.ssh/authorized_keys` + AUTH；
   写到"会被别人读取"的位置 → 存储型 XSS / SSRF 回连。
3. **EXEC + 什么 = 高危？** 已经是 RCE。缺的是"从哪个入口稳定触发"和"哪个参数传 payload"。
4. **AUTH + 什么 = 高危？** 进后台 → 找上传/模板/数据导入 = WRITE；横向 → NET。

## 三、反向搜索：从目标倒推缺口

把期望结果写成等式，再找等号左边的缺口：

```
RCE        = WRITE(webroot)      + EXEC(解析)          → 缺：任意写 或 上传绕过
RCE        = EXEC(反序列化)      + 可控入口            → 缺：gadget 链 或 触发参数
数据外泄   = READ(DB/文件)       + 可批量               → 缺：注入点 或 越权 id 遍历
横向       = AUTH(内网)          + NET(可达)           → 缺：凭据 或 出站通道
提权       = EXEC(低权)          + READ(敏感) / WRITE(高危路径)
```

拿到目标后，缺哪个就去专门补哪个 —— 这就是派工时的意图描述依据。

## 四、状态空间搜索（卡住时用）

1. **列出当前所有原语**：`list_facts` 翻一遍，把每条结论标上 READ/WRITE/EXEC/AUTH/NET。
   通常你会发现"其实已经有 4 个原语，只是没人把它们放一起看过"。
2. **两两配对**：6 类原语两两组合 21 种，逐个问"这两个能拼吗、缺什么"。
3. **三跳也算**：READ→AUTH→WRITE 很常见（读配置→进后台→上传）。
4. **记录失败组合**：拼不成的也写 fact（"READ+AUTH 走不通，因为后台无上传点"），
   避免下一个人重走。

## 五、写回要求

组合链是一条**独立的事实**，不是把已有事实复述一遍：

```
record_fact(
  summary: "组合链假设：/download?file= 的任意读 → 取 application.yml 的 DB 凭据 →
           用凭据登录 /admin（存在上传点）→ 上传 .jsp 达成 RCE",
  detail:  "已确认环节：① 任意读已实测（见 fact #123，/etc/passwd 可读）
            ② application.yml 路径已从报错堆栈得知
            未确认环节：③ 凭据是否有效 ④ admin 上传点是否存在/可解析
            下一步：先做 ③（成本最低），成功再做 ④",
  evidence: "① 已由 fact #123 提供；③④ 尚未验证",
  confidence: inferred,
  asset_ids: [目标资产]
)
```

**这条事实的价值在于"把 4 个孤立发现连成一条可执行的路线"**，规划者据此就能派出精确的意图。
不要把它写成 finding——只有最后一跳真的打穿才算 finding。

## 六、禁忌

- 不要为了"凑链"把未验证的猜测写成 `observed`。
- 不要在一条意图里同时打整条链（跨 3+ 跳的链必须分步派，规划者会拆）。
- 不要重复游说规划者：同一条链只写一次事实；有新证据时更新 detail 而不是新建一条。
