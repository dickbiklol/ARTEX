# Web / API 漏洞打法手册

每个类都给出：**入口信号 → 最少试探（probe_attempts 的下限）→ 确认标准 → 常见假阳性**。
"最少试探"是 `record_fact` 里 `probe_attempts` 该填的数字下限，达不到就别写否定结论。

---

## 1. SQL 注入

- **入口信号**：数值/字符串参数、排序字段、`LIMIT`、JSON 体、Cookie、`X-Forwarded-For` 入库
- **最少试探 6**：`'` 破引号、布尔对 `' AND 1=1--` / `' AND 1=2--`、时间盲 `SLEEP(5)`、报错型、
  JSON 体注入、`Content-Type` 切 form/multipart、二次编码绕过 WAF
- **确认**：布尔对响应差异稳定可复现 / 时间盲延迟随 `SLEEP(n)` 线性变化 / 报错泄露 SQL 片段
- **假阳性**：`SLEEP` 被前置缓存吞掉（先测无注入参数的基线耗时）；WAF 拦截页伪装成 500；
  随机延迟导致的"时间盲"（同一 payload 连发 3 次看方差）

## 2. XSS（反射 / 存储 / DOM）

- **入口信号**：参数回显在 HTML、搜索结果、个人资料、评论、文件名、`Referer` 入库
- **最少试探 5**：`<script>`、属性逃逸 `"><img onerror>`、`javascript:` 伪协议、
  标签变形 `<svg onload>`、编码绕过（HTML 实体 / Unicode / 大小写）
- **确认**：**浏览器上下文真实执行**（DOM 里能看到节点、或弹窗/回调），不是"字符串出现在响应里"
- **假阳性**：HTML 实体已转义但仍搜到子串；`Content-Type: application/json` 里的回显；
  只做反射不执行（要看是否进入 `innerHTML`）

## 3. SSTI

- **入口信号**：模板名/主题/邮件模板参数、错误页回显用户输入、`{{ }}`/`${ }` 出现在响应
- **最少试探 5**：`{{7*7}}`、`${7*7}`、`#{7*7}`、`<%= 7*7 %>`、`{{7*'7'}}`（判引擎）
- **确认**：响应中出现 `49` / `7777777`（区分 Jinja2 vs Twig）
- **假阳性**：`{{7*7}}` 只是碰巧出现在静态文本里

## 4. 命令注入 / RCE

- **入口信号**：`ping`/`nslookup`/`convert`/`backup`/`filename` 类参数、系统工具封装接口
- **最少试探 6**：`;id`、`|id`、`&&id`、反引号、`$()`、换行 `%0a`、编码绕过
- **确认**：命令输出回显；无回显用 DNS/HTTP 外带（`curl {collab}`）
- **假阳性**：只有 500 没有输出；黑名单命中但实际未执行

## 5. 路径穿越 / 任意文件读取

- **入口信号**：`file=`/`path=`/`download`/`template`/`lang`/`img`/静态资源代理
- **最少试探 5**：`../../etc/passwd`、`....//....//`、`%2e%2e%2f`、绝对路径 `/etc/passwd`、
  Windows `..\..\win.ini`、后缀截断 `passwd%00.png`
- **确认**：读到可识别内容（`root:x:0:0`）
- **假阳性**：回显了错误页里的路径字符串，不是文件内容

## 6. SSRF

- **入口信号**：`url=`/`webhook`/`callback`/`avatar`/`import`/`proxy`/PDF 生成/图片抓取
- **最少试探 5**：`http://127.0.0.1:80`、`http://169.254.169.254/latest/meta-data/`、
  `http://[::1]`、十进制 IP `http://2130706433`、`file:///etc/passwd`、DNS 外带
- **确认**：目标侧有真实出站（你的 collaborator 收到请求 / 拿到元数据）
- **假阳性**：接口直接返回"URL 不合法"；回显了你的 URL 但没有出站
- **无回显怎么办**：绝大多数 SSRF 是盲的——响应里什么都不提。**别把它记为否定**。
  先 `oob_request` 拿 host，再把 `http://{host}/` 填进 url 参数并实际发送，最后 `oob_poll` 看记录。
  `count>0` 即 confirmed。详见 skill `pentest-verification` §6。【本类漏洞的必选打法之一】

## 7. 文件上传

- **入口信号**：头像/附件/导入/主题包
- **最少试探 6**：`.php`、`.php5`/`.phtml`、双扩展 `a.php.jpg`、`Content-Type` 伪造、
  魔术字节 + 短标签、`.htaccess`、zip/归档解压穿越
- **确认**：上传后能访问并解析执行，或能读取上传目录
- **假阳性**：上传成功但目录不可访问；只改了文件名没改扩展

## 8. 越权（IDOR / BOLA / 水平垂直）

- **入口信号**：`id=`、`uid=`、`order_id`、`/api/v1/user/{id}`、GraphQL 的 `node(id:)`
- **最少试探 6**：**至少换 3 个不同身份的等价资源 id**（自己的两个 + 他人的一个），
  换 HTTP 方法、去掉请求体、用列表接口反查、GraphQL 别名批量
- **确认**：拿到**不属于当前身份**的真实数据（内容可比对）
- **假阳性**：id 不存在返回 200 空对象；自己的另一个 id 越权（同主体不算）

## 9. 认证 / 会话

- **入口信号**：登录、注册、找回密码、JWT、OAuth 回调、验证码
- **最少试探 6**：默认口令组合、用户枚举（响应差异/时序）、密码重置 token 可预测、
  JWT `alg:none`/弱密钥/`kid` 注入、OAuth `redirect_uri` 白名单绕过、验证码复用
- **确认**：真实登录成功 / 拿到他人 token / 重置他人密码
- **假阳性**：登录失败页文案不同被当成"用户存在"（需时序或状态码双证据）

## 10. 业务逻辑

- **入口信号**：下单、优惠券、退款、积分、审批、库存、并发
- **最少试探 4**：负数/超大数、并发重复提交、步骤跳过（直接调第 3 步）、
  价格/数量前端校验绕过、状态机逆序
- **确认**：造成实际业务影响（0 元下单、重复领券、越级审批）
- **假阳性**：只改了前端显示，后端已校验

## 11. 反序列化 / 表达式注入

- **入口信号**：`viewState`、`session`、`token`、序列化 cookie、`SpEL`/`OGNL` 参数
- **最少试探 4**：识别格式（`rO0AB` = Java 序列化 base64）、已知 gadget 链、
  `%{7*7}`（Struts）、`T(java.lang.Runtime)`（SpEL）
- **确认**：命令执行或可控回显
- **假阳性**：只是 base64 不是序列化

## 12. 配置 / 信息泄露

- **入口信号**：`/.git/config`、`/.env`、`/actuator/env`、`/swagger-ui.html`、`/debug`、
  备份文件 `www.zip`/`.bak`/`.swp`、`/phpinfo.php`
- **最少试探 4**：常见敏感路径字典 + 目录列表 + 错误页堆栈 + 响应头泄露
- **确认**：读到凭据/源码/内网地址等真实敏感内容
- **假阳性**：catch-all 返回 200 + 首页内容（务必先定尺！）

---

## 用法

1. 领到的意图属于哪一类？打开对应小节，把"最少试探"当**待办清单**逐条走完。
2. 每走完一种打法，就在 detail 里记一行"试过 X → 结果 Y"。走完再写 fact。
3. 走完了仍无信号 → `record_fact`，`probe_attempts` = 实际次数，`confidence=observed`。
4. 中途出现新线索（新参数、新端点、内网地址、凭据）→ **立刻写进 fact 交规划者**，
   不要自己越界扩大范围。
5. 某一类卡住超过 2 次同样失败 → 换类，别死磕（`zero-day-discovery` 提供深挖路径）。
