# 红队 OPSEC（降低噪音、避免被封、保护证据）

**为什么单独成篇**：一次失败的"安全测试"通常不是因为技术打不进去，而是因为
**打得太吵被 WAF 封了 IP、触发了 SOC 告警、或者把目标打挂**。噪音控制直接决定测试能否做完。

## 一、请求节奏（最容易被忽略的一条）

| 场景 | 做法 |
|---|---|
| 目录/参数枚举 | 并发 ≤ 20，加 `-rate`/`--delay`，先小字典再大字典 |
| 注入/爆破类 | 单线程或双线程，失败即退避 |
| 认证接口（登录/OTP） | **串行**，遇到锁定风险立即停（会锁死真实账号） |
| 大范围扫描（nmap/naabu） | 分网段、分时段；避免 `-T4` 以上 |
| 触发过 WAF 403 后 | 退避 60s，换 UA/路径再试，不要连续重试 |

```
原则：宁可慢，不要被封。被封 IP 就等于这个目标做完了。
```

## 二、指纹规避（只在必要时）

- 默认**不要**伪装成内部流量或伪造来源（除非授权明确允许）。
- 需要绕过 WAF 时，按 `component-vuln-intel` 的受阻阶梯来（换 UA → 换引擎 → 换路径），
  **优先换"请求形态"，而不是伪造"身份"**。
- 不要使用会触发 EDR 的工具（mimikatz 等），除非任务明确要求且已获批准。

## 三、避免破坏（比避免发现更重要）

| 危险动作 | 安全替代 |
|---|---|
| 删除/覆盖 | 只读，或写一个唯一命名的证明文件 |
| 大批量写入 | 只写 1 条并立即删除 |
| 上传 webshell | 用无害的标记文件证明"能上传"，除非授权要求 getshell |
| 密码爆破 | 先用 3–5 个常见口令，未确认锁定策略前不放大字典 |
| 修改配置/权限 | 用只读方式证明"能改"，不真的改 |
| 压力测试类 payload | 不用（sleep 类用固定 5s，不用大数） |

**测试前问自己**：这个动作如果被目标当真实攻击处理，会造成什么？
如果答案是"服务中断/数据损坏/账号锁定"，就不要做。

## 四、凭据与敏感数据

- 凭据**原文只写进 fact 的 detail**，summary 和 finding 正文里脱敏
  （`ASIA****（过期 2026-10-27）`）。
- 不要用真实凭据做"顺手"的读操作；只验证它有效（`sts get-caller-identity` / `id`）。
- 抓到的个人数据（手机号/身份证/邮箱）：**只取前 3–4 位 + 掩码**写进证据。
- 不把凭据写进命令历史（用环境变量或临时文件，用完删）。

## 五、证据留存（事后要能复盘）

每一条 finding 都必须能回溯到"哪个请求/哪条流量"：

```
report_finding(..., traffic_refs: [
  {traffic_id: "<baseline>", role: "baseline", note: "正常请求，耗时 0.08s"},
  {traffic_id: "<proof>",    role: "proof",    note: "注入后 5.02s，返回数据"}
])
```
录制代理会自动留痕；`traffic_search` / `traffic_get` 能翻原文。
**不要**只凭记忆写报告——三个小时后你会记不清 payload。

## 六、被封/被限之后的处理

1. **停**：立即停止该方向的请求（继续打只会延长封禁）。
2. **记**：`record_fact(confidence:observed, probe_attempts:N)` 写清
   "在第 N 次请求后开始返回 403/429，形态为 WAF 拦截页"。
3. **换**：换路径/换参数位置/换编码/换源（若授权允许）再试。
4. **报**：如果整个资产被封，写进 fact 交规划者——它会调整顺序，先做别的资产。

## 七、红线

- 不伪造身份、不冒用他人凭据、不攻击授权范围外的资产。
- 不做任何"不可逆"操作，除非授权文件明确写了。
- 触发 SOC 告警不算失败，但**隐瞒**触发告警是。
